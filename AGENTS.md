# AGENTS.md — o7am.github.io

This document describes how the o7AM website is built, deployed, and structured so that agents and developers can work on it effectively.

## Overview

The site is a **static HTML site** generated by a Python script. Content and copy live in YAML under `data/`. Jinja2 templates under `templates/` are rendered once per locale (Polish `pl` and English `en`). The output is written to `out/` and deployed to **GitHub Pages** via a GitHub Actions workflow. The published site is served from the contents of `out/` (not from the repo root).

- **Site URL:** https://o7.am  
- **Locales:** Polish (root), English (`en/`)  
- **Build:** `build.py` → writes to `out/`

---

## Build process

### Environment setup (once per machine)

Tool versions (Python, [uv](https://github.com/astral-sh/uv), [just](https://github.com/casey/just), Node) are pinned in `mise.toml` and installed via [mise](https://mise.jdx.dev/):

1. Install mise: `curl -fsSL https://mise.run | sh` (or `brew install mise`), then activate it in your shell (`mise activate zsh`/`bash` — see mise docs) so its shims are on `PATH`.
2. From the repo root: `mise trust` (first time only) then `mise install` — reads `mise.toml` and installs the pinned Python, uv, just, and node.
3. That's it — `just build` (below) handles Python deps itself via `uv run`, which reads `pyproject.toml`/`uv.lock` and creates/updates `.venv` automatically on first run.

No manual `venv`/`pip install` step is needed once mise + uv are set up this way.

### Local build

- **Recommended:** `just build` (runs `uv run python build.py`; uv auto-creates `.venv` and installs deps from `pyproject.toml`/`uv.lock` on first run).
- **Alternatively:** `uv run python build.py` directly (same thing `just build` calls).

The script:

1. Loads YAML from `data/` (i18n, blogs, portfolios).
2. For each locale (`pl`, `en`), generates a list of pages (output path, template name, context): home, blog list, portfolio list, services overview, contact, three service subpages (`services/it.html`, `services/3d.html`, `services/de.html`), each blog post, and each portfolio item.
3. Renders each page with Jinja2, writing HTML into `out/` (e.g. `index.html`, `en/index.html`, `blog.html`, `portfolios/3d_prints.html`, etc.). The portfolio item with slug `emoji` renders with `portfolio_emoji.html` instead of the generic `portfolio_item.html`; all other slugs use `portfolio_item.html`.
4. Copies static files and dirs from the repo root into `out/` (see [Static files](#static-files)).
5. Writes `out/en.html` as a redirect to `en/index.html` (for `/en`-style URLs on GitHub Pages).

**Output directory:** `out/`. It is in `.gitignore`; do not commit it. The CI workflow uploads `out/` as the GitHub Pages artifact.

### Preview locally

- `just serve` — serves `out/` at http://localhost:8000.

### Other `just` recipes

- `just sync-en` — PL/EN content sync check (see [PL/EN sync command](#plen-sync-command)).
- `just fonts` — runs `scripts/download-fonts.py` to (re)download Fira Sans and Oswald `.woff2` files into `assets/fonts/`, so the site self-hosts fonts instead of pulling from a CDN. Run once, or when updating font versions.
- `just perf` — runs `scripts/run-performance-audit.py`, a Lighthouse performance audit against the live `https://www.o7.am` site (median of multiple runs for stability). Requires Node/npx and Chrome/Chromium. Not part of the build; a manual/CI-adjacent check.

### Deployment (CI)

- **Workflow:** `.github/workflows/deploy-pages.yml`
- **Trigger:** Push to `main`
- **Steps:** Checkout → install uv + Python via `astral-sh/setup-uv` → `uv run python build.py` (installs deps from `pyproject.toml`/`uv.lock` automatically) → upload `out/` as `upload-pages-artifact` → `deploy-pages` deploys that artifact to GitHub Pages.
- **Pages source:** In repo **Settings → Pages**, the source must be **GitHub Actions** (not “Deploy from a branch”).

## File and directory reference

### Root

| File / dir       | Purpose |
|-----------------|--------|
| `build.py`      | Static site generator. Loads `data/*.yaml`, renders `templates/`, writes to `out/`, copies static assets. |
| `mise.toml`      | Pins tool versions (Python, uv, just, node) for [mise](https://mise.jdx.dev/); `mise install` sets up a machine for local dev. See [Environment setup](#environment-setup-once-per-machine). |
| `justfile`      | Commands: `just build`, `just serve`, `just sync-en`, `just fonts`, `just perf`. Uses `uv run` throughout. |
| `pyproject.toml` | Single source of truth for Python deps (Jinja2, PyYAML). `uv run` (local and CI) auto-manages `.venv` from this + `uv.lock`. |
| `uv.lock`        | Locked dependency versions for `pyproject.toml`, generated/updated by `uv`. Commit changes when deps change. |
| `style.css`      | Global styles (full stylesheet, loaded non-blocking). Copied into `out/` as-is. |
| `app.js`        | Global front-end script (e.g. menu, lazy loading, emoji-grid search). Copied into `out/`. |
| `theme.js`      | Light/dark theme toggle script (persists choice, e.g. to `localStorage`). Copied into `out/`. |
| `llms.txt`      | [llms.txt](https://txt-llms.com/documentation) manifest for LLM search engines. Markdown summary and links; copied to `out/`. |
| `robots.txt`     | Crawler rules. Copied to `out/`. |
| `sitemap.xml`    | Sitemap for search engines. Copied to `out/`. |
| `CNAME`          | Custom domain for GitHub Pages (e.g. `o7.am`). Copied to `out/`. |
| `.gitignore`     | Ignores `out/`, `.venv/`, `.worktrees/`, `docs/`, macOS junk (`.DS_Store`, `._*`). |
| `AGENTS.md`      | This file. |

### `data/`

All content and copy used by the build. Keys are referenced in templates (e.g. `t.nav.services`, `item.title[locale]`).

| File | Purpose |
|------|--------|
| `data/i18n.yaml` | Per-locale strings: nav labels, meta titles/descriptions, services headings, blog/portfolio/contact page strings, footer. Structure: `pl` / `en` → `nav`, `meta`, `services`, `blog`, `portfolio`, `contact`, `footer`. |
| `data/blogs.yaml` | List of blog posts. Each: `id`, `slug` (filename), `title`/`description`/`body`/`subtitle` per locale, `date`, `image`. Rendered with `blog_post.html`. |
| `data/portfolios.yaml` | List of portfolio items. Each: `id`, `slug`, `title`/`image`/`body` per locale, optional `gallery`. Rendered with `portfolio_item.html`, except slug `emoji` which renders with `portfolio_emoji.html`. |

### `templates/`

Jinja2 templates. The build passes a shared context: `base` (path to **locale root** — use for same-locale page links so nav stays in the current language), `root` (always `/`, for static assets: CSS, JS, `assets/`), `locale`, `t` (i18n for current locale), `site_url`, `canonical_url`, `alternate_*`, `other_lang_href`, plus page-specific vars.

| Template | Purpose |
|----------|--------|
| `base.html` | Layout: `partials/head.html`, header, `{% block main %}`, footer; loads `theme.js` and `app.js`. |
| `partials/head.html` | Meta, title, description, Open Graph, Twitter, theme-color, canonical, hreflang, GA tag, critical-CSS inline, async full stylesheet. |
| `partials/critical.css` | Above-the-fold CSS (theme variables, layout, header, hero) inlined into `<head>` so first paint doesn't wait on `style.css`. |
| `partials/header.html` | Logo, nav (services submenu, portfolio, blog), theme toggle, language switcher, contact button. Uses `base` for in-locale links, `t.nav.*`, `other_lang_href`. |
| `partials/footer.html` | Footer content and links, including the Ko-fi support link in the socials row (first icon). |
| `index.html` | Homepage. |
| `blog.html` | Blog listing; receives `blogs`. |
| `blog_post.html` | Single post; receives `blog`, `title`, `description`. |
| `portfolio.html` | Portfolio listing; receives `portfolios`. |
| `portfolio_item.html` | Single portfolio item (generic): title, image, optional body, optional gallery; receives `item`. |
| `portfolio_emoji.html` | Emoji/kaomoji grid portfolio page (both locales use this one template, driven by `locale`); includes `partials/portfolio_emoji_content.html` for the searchable grid markup. |
| `partials/portfolio_emoji_content.html` | The actual emoji/kaomoji grid + search box markup included by `portfolio_emoji.html`. |
| `services.html` | Services overview. |
| `service_it.html` | IT support service page. |
| `service_3d.html` | 3D printing service page. |
| `service_de.html` | Data Engineering service page. |
| `contact.html` | Contact page. |

### `assets/`

Images and other static assets. Copied as a whole into `out/assets/` (replace). Paths in data/templates are relative to site root (e.g. `assets/portfolios/1/cover.jpg`). Includes `assets/fonts/` (self-hosted Fira Sans / Oswald `.woff2`, populated by `just fonts`).

### `scripts/`

| Script | Purpose |
|--------|--------|
| `scripts/sync-en-from-pl.py` | **PL/EN sync check.** Compares Polish vs English content in `data/i18n.yaml`, `data/blogs.yaml`, and `data/portfolios.yaml`. Reports: keys present in PL but missing in EN; EN values identical to PL (likely untranslated). Run: `just sync-en` or `uv run python scripts/sync-en-from-pl.py`. Use `--format json` for machine output; use `--suggest` to print suggested EN snippets (copy from PL) for manual translation. See [PL/EN sync command](#plen-sync-command) below. |
| `scripts/download-fonts.py` | Downloads Fira Sans (Mozilla Fira repo) and Oswald (Google Fonts) `.woff2` files into `assets/fonts/` so the site self-hosts fonts instead of pulling from a font CDN. Run: `just fonts`. |
| `scripts/run-performance-audit.py` | Runs a Lighthouse performance audit against the live `https://www.o7.am`, using multiple runs and the median result for stability. Requires Node/npx and Chrome/Chromium. Run: `just perf` (optionally `PERF_RUNS=5 just perf`, or `--single` for one run). |

### `.github/workflows/`

| File | Purpose |
|------|--------|
| `deploy-pages.yml` | Builds the site with Python, uploads `out/` as the Pages artifact, deploys to GitHub Pages. |

### `.cursor/rules/`

| File | Purpose |
|------|--------|
| `pl-en-sync.mdc` | Cursor rule mirroring the [PL/EN sync command](#plen-sync-command) below: reminds Cursor to run `just sync-en` after editing `data/*.yaml`. |

### Generated in `out/` (do not edit by hand)

- `out/en.html` — Redirect to `en/index.html` (so `/en.html` works on GitHub Pages).
- All HTML under `out/` and `out/en/` is produced by `build.py`.

## Adding or changing content

- **Copy / UI strings:** Edit `data/i18n.yaml` (per locale).
- **Blog posts:** Add or edit entries in `data/blogs.yaml`; keep `slug` stable (used in URLs and filenames).
- **Portfolio items:** Add or edit entries in `data/portfolios.yaml`. Use `body.pl` / `body.en` for HTML description. The generic `portfolio_item.html` template covers most items; the `emoji` slug is special-cased in `build.py` to use `portfolio_emoji.html` instead — to add another custom-layout portfolio page, add a similar `if slug == "..."` branch in `build.py`'s page-building loop and create the corresponding template.
- **New pages (e.g. new service):** Add a new template, then in `build.py` extend the `pages` list (per locale) with the correct output path, template name, and context.

### Theme-aware styling (light/dark)

The site supports a light/dark theme (`data-theme="light"` or `"dark"` on `<html>`, toggled by `theme.js`). **Any new or changed text and UI must be theme-oriented:** use CSS variables (e.g. `var(--text-primary)`, `var(--bg-page)`, `var(--header-text)`) instead of hardcoded colors like `#fff` or `#000`. That way new copy, borders, and backgrounds respect the user's theme. See `style.css` and `templates/partials/critical.css` for the existing theme variables and `[data-theme="light"]` overrides.

### Analytics (Cloudflare Web Analytics)

`templates/partials/head.html` loads the [Cloudflare Web Analytics](https://www.cloudflare.com/web-analytics/) beacon (`static.cloudflareinsights.com/beacon.min.js`) on every page. It's cookieless and doesn't collect personal data, so **no cookie-consent banner is required** for it. The `data-cf-beacon` token in that script tag must be a real token from the Cloudflare dashboard (Analytics & Logs → Web Analytics → Add a site) — it does not require moving DNS/hosting to Cloudflare.

The site previously used Google Analytics (`gtag.js`) plus a half-built cookie-consent banner in `app.js` that was never wired to any template element (`#cookie-banner` didn't exist) — both were removed. If GA or another tracker that sets cookies/identifiers is ever reintroduced, it needs a real consent gate (default-denied Consent Mode + an actual banner) before it can fire for EU/UK visitors — don't add tracking scripts to `head.html` without one.

### Support link (Ko-fi)

A "support us" / "buy me a coffee" link points to Ko-fi (`https://ko-fi.com/o7am_`). It appears in the **footer** as the first social icon (same style as Instagram/LinkedIn) and on the **contact page** as a green round button with a coffee icon. Copy: `footer.support_us`, `contact.support_line`, `contact.support_cta` in `data/i18n.yaml`. No backend; link-only.

### PL/EN sync command

To check whether English content is in sync with Polish (e.g. after adding new copy in PL):

- **Run:** `just sync-en` or `uv run python scripts/sync-en-from-pl.py` (from repo root).
- **Output:** A report listing (1) keys present in PL but missing in EN (`data/i18n.yaml`), and (2) EN values that are identical to PL (often intentional e.g. "Portfolio", "Data Engineering"; review and translate if not).
- **Options:** `--format json` for machine-readable output; `--suggest` to print suggested EN snippets (copy from PL) for missing or identical i18n keys, for manual translation.
- **When to run:** After editing `data/i18n.yaml`, `data/blogs.yaml`, or `data/portfolios.yaml`; before committing large content changes; when preparing a release.

## Locales and URLs

- **Polish (default):** Root paths, e.g. `/`, `/portfolio.html`, `/portfolios/3d_prints.html`.
- **English:** Under `en/`, e.g. `/en/index.html`, `/en/portfolio.html`, `/en/portfolios/emoji.html`.
- **Language switcher:** Uses `other_lang_href` (e.g. `en/index.html` from PL index). For the EN homepage, use `https://o7.am/en/index.html` or `https://o7.am/en.html` (redirect).
- **Nav persistence:** Header and footer links use `base` (locale root), so clicking e.g. Contact from the English site goes to `/en/contact.html` and keeps the chosen language.

## Summary for agents

1. **Build:** First time on a machine, run `mise install` (see [Environment setup](#environment-setup-once-per-machine)); then `just build` or `uv run python build.py`; output is in `out/`.
2. **Content:** Edit YAML in `data/`; templates in `templates/` consume it.
3. **Deploy:** Push to `main`; the workflow builds and deploys `out/` to GitHub Pages.
4. **Custom-layout portfolio pages:** Special-case the slug in `build.py`'s page loop (like `emoji` → `portfolio_emoji.html`) and add the corresponding template under `templates/`.
5. **New static assets:** Put them in `assets/` or add to `STATIC_FILES` in `build.py` if at root; they will be copied into `out/` on build.
6. **Theme-aware UI:** Any new or changed text/UI must use CSS variables (e.g. `var(--text-primary)`) so it works in both light and dark theme; avoid hardcoded colors.
7. **Support link:** Ko-fi lives in the footer (first social icon) and on the contact page (green coffee button); copy in i18n (`footer.support_us`, `contact.support_*`).
8. **PL/EN sync:** After editing `data/i18n.yaml`, `data/blogs.yaml`, or `data/portfolios.yaml`, run `just sync-en` (or `uv run python scripts/sync-en-from-pl.py`) to see if EN is missing keys or still has copy identical to PL (needs translation).
9. **Other scripts:** `just fonts` re-downloads self-hosted webfonts; `just perf` runs a Lighthouse audit against the live site. Neither runs as part of `just build` or CI.
